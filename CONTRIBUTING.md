# Contributing

Thank you for contributing to the DMDE Master Handbook. This repository is intended to be a clear, consistent, and reviewable source of truth for DMDE documentation.

## Contribution Principles

- Keep documentation accurate, concise, and useful for decision-making.
- Prefer small, focused changes over broad unrelated edits.
- Preserve the existing folder and file naming conventions.
- Use clear headings, tables, lists, and examples where they improve readability.
- Avoid committing secrets, credentials, internal-only tokens, or sensitive personal data.

## Workflow

1. Create a topic branch for your change.
2. Update or add Markdown files in the appropriate documentation area.
3. Add supporting diagrams or images under `assets/` when needed.
4. Update `CHANGELOG.md` for meaningful additions, changes, removals, or fixes.
5. Run basic checks before submitting a pull request:
   - Review Markdown rendering.
   - Check links that you add or modify.
   - Confirm no generated temporary files are included.
6. Open a pull request with a concise title and a summary of the change.

## Documentation Style

- Start each document with a single `#` heading that matches the document topic.
- Use sentence case for headings unless a product name or acronym requires otherwise.
- Prefer active voice and concrete guidance.
- Use tables for structured reference material.
- Include "TODO" markers only when follow-up work is intentional and tracked.

## Review Expectations

Reviewers should verify that changes are placed in the correct section, follow naming conventions, avoid duplication, and do not conflict with existing architecture or governance guidance.
