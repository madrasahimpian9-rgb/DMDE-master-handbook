# Security Policy

## Reporting Security Issues

Do not open a public issue for security vulnerabilities, leaked credentials, sensitive data exposure, or abuse cases.

Report security concerns privately to the project maintainers using the approved internal reporting channel for the DMDE project. If no internal channel is available, contact the repository owner or organization security contact directly.

## What to Include

When reporting a security concern, include:

- A concise description of the issue.
- Affected files, systems, or documentation areas.
- Steps to reproduce or validate the concern, when applicable.
- Potential impact and suggested remediation, if known.
- Whether any secret, credential, token, or personal data may have been exposed.

## Handling Expectations

Maintainers should acknowledge valid reports, assess impact, coordinate remediation, and avoid public disclosure until the issue is resolved or an agreed disclosure plan is in place.

## Documentation Security Guidelines

- Do not commit real secrets, credentials, tokens, private keys, or production configuration values.
- Use placeholders for examples, such as `example-token` or `REPLACE_ME`.
- Avoid publishing sensitive architecture details that could increase operational risk unless approved.
- Review diagrams and screenshots for accidental exposure before committing them.
