# DMDE-00.03 Scope

## Scope Statement

The DMDE Master Handbook covers documentation needed to align stakeholders, guide platform architecture, support delivery teams, and maintain governance across business, technical, and operational domains.

## In Scope

- Project charter, vision, objectives, roadmap, stakeholders, and success criteria.
- Business analysis artifacts including capabilities, domains, processes, personas, functional requirements, non-functional requirements, risks, and business rules.
- Enterprise architecture guidance covering principles, standards, decisions, data, AI, integration, deployment, security, and governance.
- Domain architecture books for identity, organization, academic structure, student management, teacher management, curriculum, assessment, reporting, portals, AI services, and supporting services.
- Development guidance for coding, Git workflow, branching, APIs, events, logging, error handling, testing, deployment, and release management.
- Reference documentation, appendices, diagrams, templates, examples, and supporting assets.

## Out of Scope

- Production application source code unless it is a reference implementation or example.
- Real credentials, secrets, private keys, production configuration values, or sensitive personal data.
- Final business approval of requirements without stakeholder review.
- Replacement of project management tools, issue trackers, or operational monitoring systems.

## Dependencies

| Dependency | Impact |
| --- | --- |
| Stakeholder availability | Required for validating requirements, scope, priorities, and acceptance criteria. |
| Architecture decisions | Required before standards and domain guidance can be considered stable. |
| Security review | Required before publishing sensitive architecture, integration, or operational details. |
| Delivery roadmap | Required to keep documentation priorities aligned with implementation sequencing. |

## Change Control

Scope changes should be documented with the reason for change, affected documents, expected impact, decision owner, and approval status. Significant scope changes should also be reflected in the roadmap and changelog.
