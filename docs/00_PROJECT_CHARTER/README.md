# Project Charter

The project charter section defines why DMDE exists, what it intends to deliver, who is involved, how success is measured, and how the work is sequenced. It is the first reference point for sponsors, product owners, architects, delivery teams, and governance stakeholders.

## Documents

| Document | Purpose |
| --- | --- |
| `DMDE-00.01-Project-Vision.md` | Describes the desired future state and guiding vision for DMDE. |
| `DMDE-00.02-Project-Charter.md` | Summarizes mandate, governance, assumptions, constraints, and authorization. |
| `DMDE-00.03-Scope.md` | Defines in-scope work, out-of-scope boundaries, dependencies, and change control. |
| `DMDE-00.04-Objectives.md` | Captures strategic, product, delivery, operational, and adoption objectives. |
| `DMDE-00.05-Stakeholders.md` | Identifies stakeholder groups, responsibilities, engagement model, and communication needs. |
| `DMDE-00.06-Roadmap.md` | Lays out phased delivery from foundation through continuous improvement. |
| `DMDE-00.07-Success-Criteria.md` | Defines measurable success indicators and evidence for acceptance. |

## Maintenance Guidance

- Review this section at the start of every major planning cycle.
- Update project assumptions and risks when governance decisions change.
- Keep scope, roadmap, and success criteria aligned with approved priorities.
- Record material charter changes in the changelog and decision history.
