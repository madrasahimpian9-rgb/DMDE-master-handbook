# EA-00.02 Architecture Principles

## Principles

| Principle | Guidance |
| --- | --- |
| Business-aligned architecture | Architecture choices must support documented business capabilities and objectives. |
| Domain ownership | Each domain owns its rules, data responsibilities, and published contracts. |
| Secure by default | Identity, authorization, data protection, and auditability are required by design. |
| Contract-first integration | APIs, events, schemas, and error behavior are documented before broad consumption. |
| Observable operations | Services must provide logs, metrics, traces, health checks, and actionable alerts. |
| Evolutionary design | Prefer reversible decisions and incremental migration paths where possible. |
| Data as a governed asset | Shared data definitions and ownership must be explicit. |
| Documentation is part of delivery | Architecture documents must be updated when decisions or behavior change. |

## Review Questions

- Which business capability does the decision support?
- What domain owns the data, workflow, or contract?
- What security, privacy, and audit controls are required?
- How will the decision be tested, deployed, observed, and rolled back?
