# EA-00.03 Reference Architecture

## Architecture Layers

| Layer | Responsibility |
| --- | --- |
| Experience layer | Web, mobile/PWA, public portal, dashboards, and user-facing workflows. |
| Application layer | Use cases, orchestration, validation, and workflow coordination. |
| Domain layer | Business rules, domain models, lifecycle states, and invariants. |
| Integration layer | APIs, events, adapters, webhooks, message contracts, and external connectivity. |
| Data layer | Operational stores, reporting stores, search indexes, documents, and metadata. |
| Platform layer | Identity, configuration, observability, deployment, security, and shared services. |

## Reference Flow

1. Users interact through the experience layer.
2. Application services coordinate use cases and enforce access decisions.
3. Domain components apply business rules and publish state changes.
4. Integration components expose contracts or consume external capabilities.
5. Data components persist owned records and publish reporting-ready outputs.
6. Platform capabilities provide security, operations, and governance support.

## Architecture Constraints

- Domains should not bypass ownership boundaries by directly modifying another domain's data.
- Shared platform services must avoid becoming a dumping ground for domain logic.
- Reporting models must identify source systems and transformation rules.
