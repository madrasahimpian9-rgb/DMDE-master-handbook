# EA-00.04 Shared Kernel

## Purpose

The shared kernel defines carefully governed concepts and platform capabilities used across multiple DMDE domains. It should remain small to avoid unnecessary coupling.

## Shared Concepts

| Concept | Description |
| --- | --- |
| User identity | The platform representation of a user account and authentication subject. |
| Role and permission | Authorization concepts used to evaluate access to capabilities and data. |
| Organization context | Institution, unit, class, group, or membership context applied to records. |
| Academic period | Shared calendar context for academic year, term, and reporting periods. |
| Audit event | Record of sensitive or material activity with actor, action, target, and timestamp. |
| Notification template | Reusable message structure with approved variables and delivery rules. |

## Governance Rules

- Add shared concepts only when at least two domains require the same stable definition.
- Document ownership, lifecycle, validation rules, and compatibility expectations.
- Prefer versioned contracts for shared APIs, events, and schemas.
