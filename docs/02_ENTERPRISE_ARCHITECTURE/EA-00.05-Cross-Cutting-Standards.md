# EA-00.05 Cross-Cutting Standards

## Standard Areas

| Area | Standard Expectation |
| --- | --- |
| Identity and access | Enforce authentication, authorization, least privilege, and audit trails. |
| API design | Use consistent naming, versioning, validation, pagination, and error formats. |
| Events | Publish meaningful business events with documented schema, producer, and consumer expectations. |
| Logging | Use structured logs with correlation identifiers and no sensitive data leakage. |
| Errors | Return actionable errors without exposing secrets or internal implementation details. |
| Configuration | Separate environment-specific settings from code and never commit real secrets. |
| Testing | Include appropriate unit, integration, contract, security, and acceptance checks. |
| Documentation | Update handbook pages when behavior, standards, or decisions change. |

## Minimum Review Criteria

Every cross-cutting change should identify affected domains, security impact, operational impact, data impact, and documentation updates.
