# EA-00.10 Integration Architecture

## Integration Principles

- Prefer explicit contracts over implicit database or file coupling.
- Version APIs, events, and schemas when compatibility may be affected.
- Use idempotency, retries, and dead-letter handling for reliable asynchronous workflows.
- Document ownership, consumers, data classification, and failure behavior for each integration.

## Integration Styles

| Style | Use When | Notes |
| --- | --- | --- |
| Synchronous API | Immediate request/response behavior is required. | Define authentication, authorization, validation, errors, and rate limits. |
| Asynchronous event | Other domains need to react to business state changes. | Define producer, schema, ordering, retry, and consumer expectations. |
| Batch import/export | Large periodic transfers are required. | Define schedule, format, validation, reconciliation, and recovery. |
| Webhook | External systems need event callbacks. | Define signing, retry behavior, payload versioning, and delivery status. |

## Contract Checklist

- [ ] Owner and consuming systems are identified.
- [ ] Data classification and privacy implications are reviewed.
- [ ] Failure modes and retry behavior are documented.
- [ ] Monitoring and support ownership are defined.
