# EA-00.15 Baseline Review

## Review Purpose

The baseline review confirms that enterprise architecture content is complete enough to guide planning, implementation, security review, and operations.

## Baseline Checklist

| Area | Review Question | Status |
| --- | --- | --- |
| Vision | Is the target architecture direction clear and aligned with project objectives? | Pending |
| Principles | Are decision principles documented and usable during review? | Pending |
| Reference architecture | Are layers, responsibilities, and constraints clear? | Pending |
| Shared kernel | Are shared concepts intentionally limited and governed? | Pending |
| Standards | Are cross-cutting standards documented for teams? | Pending |
| Decisions | Are material architecture decisions captured or queued for ADR/TDR records? | Pending |
| Security | Are identity, authorization, data protection, audit, and threat review expectations clear? | Pending |
| Integration | Are API, event, batch, and webhook expectations documented? | Pending |
| Data | Are ownership, quality, reporting, and privacy expectations captured? | Pending |
| AI | Are responsible-use controls and review expectations documented? | Pending |
| Operations | Are deployment, observability, support, and recovery expectations captured? | Pending |

## Review Outcome

A baseline can be accepted when required gaps are documented, owners are assigned, and high-risk architecture decisions have a review path.
